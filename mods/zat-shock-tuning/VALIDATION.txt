INCENDIARY GROUND FIRE
The real EML upload is applied/exported/restored against the marked disposable
revision-1273043 server fixture. Tests execute the emitted bytecode, not a separate
implementation of propagation. Native combat and VFX rendering remain unverified.

Ground impacts use the collision world transform; ground-enabled tiers calculate
the same shot coefficient without invoking direct terrain damage. Tests cover
empty ground, immediate and late entrants, disabled tiers, stationary enemy-hit
areas, independent victim timers, expiry, logout and shutdown cleanup.

collider and native damage configuration. Only its server LifeTime is replaced

zones past nine seconds, original burns and nine-second expiry for ordinary
construct grenades, and no watchdog for other grenade templates. Baseline code,
data and layout are guarded; ordinary body instructions remain intact except
entry/wait trampolines. Custom marker tags are server classification data, not new
client visuals. Full program branches, operands and stack joins are checked.

Burn ticks use neutral material feedback with existing shot fire/coefficient,
weapon/category/scaling inputs. The shipped alpha.1 repeat-hit regression remains
covered. Existing fire timing/fanout/ledger/uint32 checks and scalar/lightning
regressions remain in the validation suite. Native startup is tested separately
on loopback with a fresh disposable save; it does not exercise combat.

No production server, installed client or user save is changed by validation.

COMBAT ACCEPTANCE FOR THIS ALPHA
1. Start with fire45 only, initial_radius=0 and targets_per_spread=0: confirm normal
   hit plus timed fire damage and visual expiry on one living enemy.
2. Compare matched bows/active upgrades with no bonus, Magic Fire Damage only,
   All Fire Damage only, and both. Repeat against different resistances and after
   swapping the bow. The shot's fire component and attack coefficient are kept;
   the native attributes may still be sampled at tick time. Do not infer an exact
   damage formula from the automated model or tooltip values alone.
3. Enable initial radius, then fan-out 1 and 3. Verify nearest living mixed-species
   enemies, corpses ignored, branches converging without repeats, delay and Soaked.
4. Fire multiple arrows: burns intentionally stack per shot. Repeat with two
   unmodified clients and confirm shooter credit, client VFX and actual health.
5. Enable ground fire: move an untouched enemy into the initial radius after
   impact. Confirm a full burn, no repeat ignition, flames disappearing at expiry,
   and no ignition from entering after expiry. Test slopes, enemy movement/death,
   a second unmodified client, shooter logout and repeated arrows. The incendiary
   footprint is approximate; replication/scaling are NOT yet verified. Also shoot
   bare ground with no enemy present, then bring one into the area. Verify normal
   construct grenades still burn and that only one damage system runs per area.
6. Retest normal/disabled arrows and lightning. Apply a saved config through ESM,
   restart and confirm it is consumed. Disable/remove and apply to restore.

Fire ledger capacity is an actual native address/bytecode limit (logged on Apply),
not a user balance cap. The retained visited ledger stops further ignitions when
full and finishes current burns. It does not offer unlimited map-wide spread.

CHANGES FROM 0.3.0-alpha.1
- Candidates must pass existence, Dead-state, positive HP and caster-hostility checks.
- All faction bits queried; target distance is independent of species/faction.
- Selected IDs stored through exact uint32 views and balanced slot dispatch.
  No saved-index query reopen, float ID conversion or dependence on enumeration order.
- Unconfirmed spreaders skip their branch without canceling confirmed siblings.
- spread_delay_ms defaults to 250, before the first spread and each generation.
  Per arrow tier and spell profile. Zero yields one update. Whole uint32 milliseconds;
  countdown uses wrapping clock differences and unsigned comparisons.
- Living spreaders refresh position after the delay. Removed victims retain the
  recorded impact origin, so a killing hit can continue to living targets.
- Enabled shock-arrow templates replace the server-only five-second LifeTime
  component with an Impact flight watchdog. Missed arrows still expire; active
  propagation continues until completion, native frontier exhaustion, or other
  engine cleanup. No duration or total-hit balance cap is added.
- Partial final generations wait their configured delay before source destruction.

VALIDATION
Tests use official EML 0.2.0 through the ESM-Z adapter in a disposable dedicated
server revision 1273043 fixture. They import the actual ZIP, apply configurations,
export patched assets through upstream kfc-parser, and audit native operand types,
branch targets and stack balance. Defaults produce zero patches; restoration
returns the exact original game index. Existing scalar and old-config tests pass.

The bytecode harness executes emitted instructions with MODELED native calls.
It covers corpses and zero/negative/missing health, mixed factions, reordered
queries, 3D nearest selection, fan-out, converging branches, independent profiles,
blocked/rejected hits, failed sibling confirmation, delayed history, moving
spreaders, killing hits, exact large entity IDs, native queue reuse, finite budgets,
clock rollover, zero delay and full uint32 delays. A 1,100-target modeled chain
continues beyond five seconds. Separate flight-watchdog tests exercise misses at
4,999/5,000 ms and timer rollover. Only enabled shock templates lose LifeTime and gain a private watchdog opt-in;
other template fields are preserved. The watchdog follows the template flag,
so it also cleans up a marked projectile spawned without ammunition metadata. Previous damage-loss and
single-hop packages remain covered by regression tests.

NATIVE EVIDENCE
Read-only inspection of revision 1273043 executable SHA256:
 d7baa768eb00aa895d9f5a1cd8747ccf66858c7b542f50983092b2e3261588ee
Reflection identifies actor.StateFlag.Dead=7, the 16-bit FactionMask, current HP
reference used by an existing healing program, and LifeTime as server-only.
Native LTime returns uint32 milliseconds; Time-valued GLoad converts nanoseconds
to milliseconds. This extension stores delays as explicit uint32 milliseconds.
GLoad/GStore only accept scalar types; aliases preserve EntityId bytes exactly.
Native generic numeric arithmetic uses float32, so it is not used for ID copies.
The faction iterator destroys its cached query on exhaustion. Native damage is
queued, with completed-hit history populated by later damage processing.

LIMITS / PLAY TEST
An import, model test or successful startup is NOT a combat test. Live multiplayer
must verify actual health loss, native HP/state availability across enemy types,
250 ms cadence and VFX, independent simultaneous casts, and cleanup of misses and
completed chains. Test mixed species beside corpses with fan-out 1, then fan-out 3;
include a chain lasting over five seconds. Only loaded/queryable targets qualify.
The queue is limited by native 16-bit data offsets, not a balance setting; capacity
is logged on Apply and slots are reused. Extremely wide frontiers stop safely.
Long/wide chains can impose significant server work. Map-wide behavior is unverified.
No production server, installed client, or user save is modified by validation.
