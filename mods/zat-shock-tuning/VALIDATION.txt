Zat Shock Tuning 0.2.0-alpha.2 - validation record, 2026-10-21

Alpha.1 field report: enabling one chain tier removed arrow damage. Disabling
that tier restored it. Native executable inspection found that GLoad rejects
ItemId (0x5bfc0dbb), which the alpha.1 ammunition gate loaded before direct damage.
The native VM supports IEQ; the problem is the load's type, not the equality opcode.
Alpha.2 uses a uint32 view at the same ItemId.value memory offset. The test model
now enforces native GLoad/GStore type restrictions and shared-memory aliases.
This resolves a concrete bytecode defect; it is not a claim of a successful
live multiplayer combat retest.

Environment: Windows dedicated server, internal revision 1273043, official
EML 0.2.0 CLI invoked through ESM-Z's existing EML adapter. The server was a
separate Steam-validated installation with an isolated test world and port.

Existing scalar integration: 23 checks passed with this package.
- The upload ZIP imports, enables, and exposes src/config.lua in ESM-Z's adapter.
- Vanilla defaults produce zero modified-resource patches.
- A changed config applies 13 requested setting changes. Exporting the patched
  game data confirms spell damage/mana/targeting, chain sphere radius, lightning
  arrow damage, and the Mass Destruction radius and damage constants.
- All fields in 20 relevant exported resources were compared with clean data;
  only the expected fields changed, including untouched arrow variants.
- The eight new ice/fire/bone settings were assigned different values and
  independently decoded. Every other exported field matched the clean data.
- An old config with the new eternal_arrows section omitted still produces
  zero resource patches at vanilla settings.
- Negative settings, float32 overflow/underflow, integer overflow/fractions,
  unknown options, nonfinite numbers, and Lua syntax errors
  are rejected. The original server index remains restored after each failure.
- A valid config applies after a rejected config; repeating Apply does not
  compound changes; returning to defaults removes all resource patches.
- Restore returns the original game index byte for byte.
- Values above every previous balance cap are accepted and decoded correctly:
  targeting 60, chain radius 20, spell damage 4, mana 600, arrow damage 5,
  Mass Destruction radius 40 and damage per Intelligence 20. No clamping occurs.
- Above-former-cap values were tested as decoded data patches, not live combat.

Arrow chain checks: 24 passed (integration, structural checks and modeled native calls).
- The original alpha.1 ZIP with the exact reported settings reproduces a native
  type rejection before direct damage for enabled and unrelated ammunition IDs.
- Alpha.2 with those same settings passes the type audit and returns to the
  original direct-hit path for all tested IDs. The modeled chain is exclusive to
  level 45, with the requested radius 48, damage 3 and jump limit 20 retained.
- Disabling chains in that config restores the complete original projectile
  program while preserving the independent item/spell tuning.
- Default ZIP imports with src/config.lua selected by the manager adapter.
- Chains disabled produces no patches. All three tiers enabled modifies one
  existing Impact program, retaining its resource ID and all original data and
  layout entries. Only two original branch operands are redirected; original
  direct-hit instructions and the unrelated paths remain in place.
- Upstream kfc-parser successfully disassembles the patched program and shutdown
  path. Branch destinations/data operands are valid and stack heights agree at
  joins. Maximum analyzed stack height is 25 against capacity 256.
- Repeated apply produces identical decoded content, with no compounding.
- Zero chance or zero spread removes the chain program patch.
- Invalid probabilities, fractional/overflowing limits, nonboolean switches and
  negative damage are rejected, retaining the original game index.
- The emitted bytecode was executed with MODELED native game calls. Scenarios
  cover unrelated ammunition, blocked hits, all three arrow IDs, changing origin,
  initial killing hits, no ping-pong with native hit-history assumptions, stopping
  if hit history fails to record a victim, radius, damage, chance pass/fail,
  finite jump limits and independent tier switches. These are not engine combat
  results; the model's native semantics remain assumptions to verify in play.
- The previous alpha.1 isolated loopback dedicated server with all three chains enabled reached
  Host_Online and Run in 12.1 seconds. No clients connected and no arrows fired.
  Its temporary config was restored, process stopped, and game index restored
  byte for byte. No production server or installed client was patched.
