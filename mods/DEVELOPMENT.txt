Shock Tuning development

Build from the repository root:
    python mods/build_shock_mod.py

Output: dist/mods/Zat-Shock-Tuning-v<manifest-version>.zip and a SHA-256 checksum file.
The ZIP includes a second copy of the vanilla config as src/config.defaults.lua.
No modified game resources, third-party tools, or server saves are distributed.

Integration validation requires a DISPOSABLE, stopped dedicated-server fixture:
    python mods/validate_shock_mod.py --fixture-dir <absolute-fixture-directory>

Fixture layout:
    SHOCK_MOD_TEST_FIXTURE  (exact text: disposable-shock-mod-test)
    Server/                (complete, clean revision 1273043 server installation)
    parser/kfc-parser.exe  (upstream resource extraction CLI)
    parser/reflection_data.json (matching revision's reflection data)
    baseline/              (clean JSON export of ItemInfo, ActorSequenceResource,
                            SkillTreeResource, TemplateResource and ImpactProgram)

The marker is an explicit operator assertion that this is disposable. The test
changes its EML state and overwrites this mod's test config, then restores the
game index in a finally block. Never put the marker beside a production server.
The script needs the repository's bundled official EML 0.2.0 executable.
It does not start a server or join clients. Results and complete relevant
resource diffs are written beneath the fixture directory.

Arrow-chain alpha (0.2.0-alpha.1):
    python mods/validate_arrow_chain.py --fixture-dir <absolute-fixture-directory>

src/arrow_chain.lua emits an original Impact extension at EML apply time, using
the installed game program as its baseline. It appends code/data and redirects
two guarded branch operands. No compiled game program or parser is distributed.
The new checks export through upstream kfc-parser, audit control flow/stack use,
and run the actual emitted words with modeled native calls. They cannot prove
the native calls' live semantics or server/client authority. The alpha uses a
rapid, synchronous chain rather than a detached timed effect. The next gate is
two-client combat, including native hit-history behavior and query performance.

Alpha.2 native type regression:
    python mods/validate_arrow_chain.py --fixture-dir <absolute-fixture-directory> --regression-package dist/mods/Zat-Shock-Tuning-v0.2.0-alpha.1.zip

The optional original ZIP adds a regression check against the shipped defect.
mods/fixtures/arrow_chain_damage_report.lua preserves the user's exact setting
values. Native GLoad/GStore accept only uint32, sint32, float32, bool and Time.
ItemId is a struct even though its value occupies four bytes. Model aliases must
share memory offsets, not independent dictionary values. A successful parse,
balanced stack and boot do not establish a valid native type at execution time.

Nearest-first fan-out (0.3.0-alpha.1):
    python mods/validate_chain_fanout.py --fixture-dir <absolute-fixture-directory>

impact_builder.lua appends typed storage and emitted instructions. The shared
chain_propagation.lua implements a breadth-first circular frontier for both
arrow_chain.lua and spell_chain.lua. They each hook two native branch operands.
The spell sequence supplies a new BoolImpactConfig so other sequences sharing
that program retain its original path. No new game resource IDs are introduced.

The frontier is bounded by native 16-bit data offsets, NOT a configured total-hit
limit. Slots are reused. Capacity is logged; a full frontier stops before a write.
The engine's projectile lifetime still applies. Do not claim map-wide propagation.
All parents in one generation submit their children before RVM, and the final
partial generation yields before destroying the Impact. Pending IDs reserve
victims before native damage history is visible; never clear native hit history.

Important native semantics verified from revision 1273043:
- FromTransform.position returns world coordinates even with referenceTransform;
  compute the three coordinate deltas explicitly for distance.
- Generic AddValues/SubValues scalar math uses float32, including uint32 inputs.
  Never use it to copy IDs. Re-fetch the selected query index directly into the
  ring's EntityId output and verify identity before accepting it.
- Native ILT is signed. Uint32 ordering flips the sign bit with wrapping IAdd.
- Load ItemId/EntityId values only through uint32 views sharing the same bytes.

Tests use byte-addressed storage for aliases and dynamic ECall pointers, model
queued damage on RVM, and include IDs above 2^24/2^31. The upstream disassembler
accepts IConst variable references but panics on scalar IConst even though the
native VM accepts it; numeric constants therefore use typed data + GLoad.


0.3.0-alpha.2 supersedes the alpha.1 query-copy/lifetime notes above:
- Entity IDs are stored via uint32 aliases selected by balanced slot dispatch,
  never by reopening a query at the saved index. Padding stores slot constants.
- StateFlag.Dead plus positive optional current HP excludes lingering corpses.
- All factions queried, then IsEnemy(caster, candidate) filters hostility.
- Configurable uint32-ms delay, wrap-safe elapsed countdown, live origin refresh.
- Missing confirmation skips one queued branch instead of terminating siblings.
- Enabled arrow templates remove only server LifeTime; a guarded entry trampoline
  preserves their five-second flight timeout until the hit path owns cleanup.
  Disabled/unrelated ammo and native spell fallback retain original paths.
- See VALIDATION.txt and validate_chain_fanout.py for modeled/native distinctions.
