Fire-arrow alpha (0.4.0-alpha.1):
    python mods/validate_fire_arrows.py --fixture-dir <absolute-fixture-directory>

src/fire_arrows.lua validates per-tier profiles and emits one shared controller
into arrow_chain.lua's single guarded program plan. It must not independently
overwrite the shared projectile. Scalar validation completes before patches apply.
The fire ledger overlays the shock frontier because ammo gates are exclusive;
immutable balanced-dispatch thresholds live OUTSIDE that mutable arena. Records
have six exact uint32 fields (24 bytes); scalar ID aliases avoid native struct
GLoad errors. Both read/write dispatches cost 66*N-14 instruction words. Derive
capacity from remaining instruction and data storage and retain all visited IDs.
Do not silently reuse visited slots: zero damage still must prevent revisits.
At capacity, stop adding records, service every existing burn and then destroy.

Burn ticks retain the original Damage.fire, attack coefficient, source and native
ranged scaling inputs, while using a fire-only DamageSetup and no crit/push/stagger.
Set ignoreConsecutiveHits=false for ticks: true skips already-hit entities.
The alpha.1 model interpreted this backwards. Never derive propagation from damage history.
Each record has independent duration, unpaid tick time, spread countdown and clock.
One frame services the records present at frame start; newly added records wait
until the next frame, including a zero configured delay. A final partial tick
accounts for all configured time. Native VFX buffs are visual-only, client-known,
short-lived leases. No shared damage buff or resource ID is changed/introduced.

Reapplication is explicitly independent per-shot stacking in this alpha. Same-
shooter refresh would require shared ownership/state beyond this controller.
The native bow-bonus/attribution and unmodified-client combat matrix is still a
manual acceptance gate. Model assertions of damage inputs are not proof of the
engine formula. Isolated startup does not execute these on-hit instructions.

Nearest-first fan-out (0.3.0-alpha.1):
    python mods/validate_chain_fanout.py --fixture-dir <absolute-fixture-directory>

impact_builder.lua appends typed storage and emitted instructions. The shared
chain_propagation.lua implements a breadth-first circular frontier for both
arrow_chain.lua and spell_chain.lua. They each hook two native branch operands.
The spell sequence supplies a new BoolImpactConfig so other sequences sharing
that program retain its original path. No new game resource IDs are introduced.

The frontier is bounded by native 16-bit data offsets, NOT a configured total-hit
limit. Slots are reused. Capacity is logged; a full frontier stops before a write.
The engine's projectile lifetime still applies. Do not claim map-wide propagation.
All parents in one generation submit their children before RVM, and the final
partial generation yields before destroying the Impact. Pending IDs reserve
victims before native damage history is visible; never clear native hit history.

Important native semantics verified from revision 1273043:
- FromTransform.position returns world coordinates even with referenceTransform;
  compute the three coordinate deltas explicitly for distance.
- Generic AddValues/SubValues scalar math uses float32, including uint32 inputs.
  Never use it to copy IDs. Re-fetch the selected query index directly into the
  ring's EntityId output and verify identity before accepting it.
- Native ILT is signed. Uint32 ordering flips the sign bit with wrapping IAdd.
- Load ItemId/EntityId values only through uint32 views sharing the same bytes.

Tests use byte-addressed storage for aliases and dynamic ECall pointers, model
queued damage on RVM, and include IDs above 2^24/2^31. The upstream disassembler
accepts IConst variable references but panics on scalar IConst even though the
native VM accepts it; numeric constants therefore use typed data + GLoad.
